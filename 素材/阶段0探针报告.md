## 0-1 词缀机制（重点，结论已定）

### 机制链路（源码确认，Item.cpp / ItemEnchantmentMgr.cpp）
```
item_template.RandomProperty（DB，池 ID）
  → item_enchantment_template（DB，按 chance 权重 roll 出 1 个 ID）
  → ItemRandomProperties.dbc（条目含 enchant_id[0..2]，最多 3 个）
  → 打到装备 PROP_ENCHANTMENT_SLOT_0/1/2（槽位 3/4/5，Item.h:147-150）
  → SpellItemEnchantment.dbc（enchant 效果，type=3 EQUIP_SPELL → 施放 spell）
```

### 关键发现
1. **"2 条词缀"可完全原生**：ItemRandomProperties.dbc 一条目可挂 2-3 个 enchant。现有 2012 条里 **979 条已是复合条目**（如 ID=227 ench=(74,79,0)=耐力+智力）。POE"前缀+后缀"语义 = 条目挂 2 个 enchant 即可。
2. **enchant 效果数据在 DBC**（SpellItemEnchantment 1522 条，ID 1-3059）：type 分布 = EQUIP_SPELL(3) 1381 条 / COMBAT_SPELL(1) 74 / DAMAGE(2) 33 / RESISTANCE(4) 31。**Turtle 的属性附魔全部走"EQUIP_SPELL 引用 spell"**（如 ID=2585 spellid=24153 = 攻强+28/躲闪+1%，复合属性一个 enchant 搞定）。
3. **词缀池（服务端 DB 层）可自由扩**：item_enchantment_template 是 DB 表，想加多少词缀都行——但 roll 出的 ID 必须**存在于客户端 ItemRandomProperties.dbc**。两个选择：
   - **路线 A（零补丁，一期）**：复用现有 979 条复合条目 + 原版属性 enchant → 词缀池直接用现成组合，数值为原版水平
   - **路线 B（客户端补丁，二期扩展）**：改 ItemRandomProperties.dbc + SpellItemEnchantment.dbc 加自定义条目（挂自定义 spell）→ 自定义数值/名称/特效
4. **升级保词缀链路成立**：词缀存于物品实例（ITEM_FIELD_RANDOM_PROPERTIES_ID + PROP 槽），Eluna 可 `GetEnchantmentId` 读出、新物品 `SetEnchantment` 写回（TurtleLuaEngine.cpp:12344 已验证 API 完整，含 ApplyEnchantment 生效逻辑）。

### 遗留（游戏内实测 1）
- 造 1 件 item_template.RandomProperty=池ID 的紫装 → 掉落/生成 → 验证 2 条词缀同时生效、属性面板正确、客户端显示"of the X"类名正常。

## 0-2 宝石插槽（结论已定：无原生插槽 → 替代交互）

### 静态确认
- item_template **无 SocketColor/Content 字段**（SHOW COLUMNS 全列确认）
- Item.h/Item.cpp 无 socket 相关代码；无 GemProperties.dbc
- **1.12 原版宝石 = 消耗品直接使用施法**，无"插孔"概念

### 替代交互方案（定稿）
**宝石 = 右键使用，Eluna 给目标装备打附魔（自定义槽位），消耗宝石；换宝石 = 再使用新宝石覆盖**。
- 槽位用 TEMP(1) 或自定义：宝石效果用 SetEnchantment 打到装备固定槽
- 限制（Eluna 检查）：四色宝石同色最多 2 枚、传奇宝石仅多彩位（方案=固定"多彩槽"槽位 1 个）、诅咒宝石最多 1 枚
- 打孔器（1-8）：给装备"开孔"= 解锁宝石槽（自定义表 soulcore_arpg_sockets 记孔数）——简化版：打孔=增加可用槽位计数
- 影响系统：1-5 四色宝石 / 1-8 打孔器 / 2e 传奇宝石 / 2f 诅咒宝石 —— 全部走此交互

### 遗留（游戏内实测 2）
- 实测宝石 use → 附魔上装备 → 属性生效；同色第 2/3 颗计数限制生效；换装后附魔随装备走（TEMP 槽需确认随装备保存——1.12 TEMP 附魔有 1 小时时限，**需改持久方案**：建议用 PROP 槽位 3-6 或自定义"宝石槽"常量，Eluna 管理读写）

> ⚠️ 注意：TEMP 附魔在 1.12 有时限（TEMP_ENCHANTMENT_SLOT 通常 1 小时）。宝石持久化必须避开 TEMP 槽，用 PROP 槽（3-6）之一做"宝石槽"，Eluna 读写 + 重登恢复。

## 0-6 自定义法术（结论已定：优先复用，不新建）

### 静态确认
- **服务端 Spell.dbc：26928 条**（1.12 原版约 1.7 万 + Turtle 自定义约 1 万）——Turtle 已有海量自定义 spell
- **客户端有 patch-2~patch-Z MPQ**——Turtle 魔改客户端 DBC 的通道已存在（Spell/SpellItemEnchantment 都被扩展过）
- 服务端加载 server/data/dbc/Spell.dbc；客户端加载自身 MPQ 内 DBC —— **两端必须一致**，否则客户端显示异常

### 结论
1. **优先复用 Turtle 现有自定义 spell**（ID 段需进一步识别 2.4 万+ 段）→ 2b 三色球/2e/2f 效果尽量用现有 spell 改名改数值实现（服务端 DB 无 spell 表，**spell 数值改不了**——spell 全在 DBC！只能改引用）
   - ⚠️ 修正认知：1.12 无 spell DB 覆盖（不同于 3.35 的 spell_mod 等），**spell 数值= DBC 固定**。三色球 aura 数值只能：a) 用现有数值接近的 spell b) 改 DBC（客户端补丁）
2. 新建 spell（改 DBC）= **客户端补丁工程**（改 server/data/dbc + 打包进客户端 MPQ）——工作量不可控，**列入 C 级暂缓**；一期全部复用现有
3. 0-6 实测仅验证：高 ID 段（Turtle 自定义）spell 客户端显示正常（预计正常——Turtle 玩家一直在用）
