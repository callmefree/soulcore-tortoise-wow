# 04 移植评估与落地建议（1.12 + Eluna）

> 目标技术栈：Tortoise 1.12 + Eluna Lua 引擎（可热重载、无 C++ 改动优先）
> 已知约束：① 1.12 物品/技能 DBC 结构不同于 3.35，**3.35 的物品数据不能直接导入**，只能复刻体系；② Eluna 布尔事件语义与官方相反（写脚本先查 expectedValue）；③ gossip 三条规范（GossipClearMenu / sender=0+action / item use return false）；④ GM rank≥4 才能 .reload eluna。

---

## 0. 总体结论

- 暗黑逍遥的 **19 个 ARPG 系统中有 17 个可以在 1.12 + Eluna 上落地**（8 个低成本、9 个中成本），全部**无需改 C++**（用 SQL 建物品 + Eluna 写机制）。
- 魔改核心（3.35 worldserver.exe）实现的机制（三色球、混沌石升级、副本门控、方块功能）在 1.12 上**全部改用 Eluna Lua 重写**，反而是我们的优势：可热重载、可调参。
- 不建议做的：3.35 任务/副本数据迁移（结构不兼容，性价比低）。

## 1. 分级评估表

### 🟢 A 级：纯 SQL + 现有机制即可（建议第一批做）

| 系统 | 落地方式 | 工作量 |
|---|---|---|
| 1-33 号符文 | item_template 建 33 件 + 原生附魔（enchant）作为"使用效果"；随身商人兑换 | 半天 |
| 四色宝石 | item_template 25 件 + 宝石插槽（1.12 Turtle 有宝石系统）；限制每色 2 枚需 Eluna 计数 | 1 天 |
| 宝石书合成链 | Eluna 物品合成脚本（书页→书→宝石，3 合 1） | 半天 |
| 套装重铸 | Eluna 物品 use 事件：替换套装部件（5% 消失） | 半天 |
| 拉玛兰迪打孔器 | Eluna：给武器加孔（Turtle 无打孔机制 → 用临时附魔/自定义表模拟） | 半天 |
| 传家宝符文激活 | Eluna 检查物品使用条件 | 半天 |
| 随身小伙伴 | Eluna 召唤商人/训练师（super_hearthstone 扩展） | 半天 |
| 新手引导（艾薇儿） | Eluna gossip NPC + welcome.lua 扩展（现有 190001 模式复用） | 1 天 |
| 主城喊话机器人 | Eluna OnUpdate 定时喊话 | 2 小时 |

### 🟡 B 级：需 Eluna 写核心机制（第二批）

| 系统 | 落地方式 | 注意点 |
|---|---|---|
| 传奇宝石（20 颗×6 级） | item_template 建 120 件 + 多彩孔限制（Turtle 无多彩孔 → Eluna 限制镶嵌位置） | 效果用 Eluna aura 实现 |
| 诅咒宝石（11 颗） | 同上 + 负面效果 | 抉择玩法 |
| 三色球 | Eluna aura 计数器（3 个变量）+ 动态调属性；词缀联动 | 每颗+5% 的数值要适配 1.12 属性膨胀 |
| POE 通货（6 种） | Eluna 物品 use：混沌石=升级判定（5%/0.2%）、重铸石=部件转换、魔镜=复制 | 核心是"装备升级"链路 |
| 紫装随机词缀 ×2 | ① Turtle 原生 item_enchantment_template 词缀池（若 1.12 支持 RandomProperty）② 或 Eluna 掉落时随机打附魔 | 需先实测 Turtle 随机附魔机制 |
| 远古/太古升级链 | Eluna：检测使用混沌石 → 概率替换成 +100000/+200000 条目 | 需要**预生成全部远古/太古条目**（SQL 脚本批量） |
| 红色传奇装备 | SQL 建 66 件×15 条目 + Eluna 掉落表 | 工作量大但机械 |
| 副本通行证门控 | Eluna `OnMapEnter`：检查对应 buff/套装，无则秒杀+提示 | 秒杀用 SetHealth(1)+Kill 或直接 KillPlayer |
| 赫拉迪克方块 | Eluna 物品 use 菜单（升级/重铸/转换/分解互斥） | 复用炉石菜单模式 |
| 全职业宠物 | Eluna 召唤 + Turtle 宠物系统 | 宠物天赋另做 |

### 🔴 C 级：不建议/高成本

| 系统 | 原因 |
|---|---|
| 3.35 副本/任务数据迁移 | DBC/SQL 结构不兼容 1.12，移植性价比低 |
| 高清客户端补丁 | 1.12 客户端无对应 MPQ 体系 |
| AHBot | 3.35 专有模块；1.12 可用 Eluna 简版替代（定期刷新拍卖行商品） |

## 2. 推荐落地顺序（配合现有 Eluna 基础）

现有基础：welcome.lua（登录欢迎）、test_gossip.lua（NPC gossip 190001）、super_hearthstone.lua（炉石传送菜单+自定义坐标持久化）。

```
第 1 批（练手+立竿见影）：
  艾薇儿式新手引导 → 随身小伙伴 → 主城喊话 → 1-33 号符文
第 2 批（ARPG 核心体验）：
  四色宝石 → 宝石合成链 → 三色球 → POE 通货+远古/太古升级链
第 3 批（深度玩法）：
  传奇/诅咒宝石 → 红装 → 副本通行证门控 → 赫拉迪克方块
```

## 3. 技术风险与对策

| 风险 | 对策 |
|---|---|
| Turtle 1.12 无多彩宝石孔 | Eluna 限制宝石只能装指定槽位（自定义表记录孔位） |
| 随机附魔机制差异 | 先实测 Turtle `item_enchantment_template` 是否生效；不行就 Eluna 掉落钩子打附魔 |
| 3.35 属性数值照搬会爆炸 | 1.12 属性膨胀远小于 3.35，**所有数值按 1.12 装备水平重做**（参考 Turtle 60 级毕业数值） |
| 副本门控秒杀误伤 | 门控检查写白名单（GM/豁免物品），调试期留关闭开关 |
| 大量 SQL 生成（远古/太古/红装条目） | 写 Python 脚本批量生成 SQL（参照原版物品+20%规则），不用手写 |
| Eluna 事件语义（boolean 相反） | 每个 use/gossip 事件先查 TurtleLuaEngine.cpp 调用点 expectedValue（工作记忆已记录规则） |
