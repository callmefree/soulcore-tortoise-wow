# P1 方案 A 执行包 — 原生 IRP 保留 + 扣 1 条换全新附魔（4 步闭环）

> 状态：P0 已打通（`Worn Shortsword` 出现“耐力之/雄鹰之”且白色显示，说明 `random_property→504` 链路通）。白色是原生行为（`type=1 STAT`），不是 bug。  
> 目标：**保留原生随机属性框架，只扣 1 条换 1 条全新附魔**，复用你现成工具链 70%。

---

## 0. 一句话原理（帮你把“扣一个”翻译成 DBC 语言）

你现在 454 池是 `16 选 1` → 每件白装随机得 1 个后缀（如“耐力之”“雄鹰之”）。  
P1-A 就是：**新建一个池 `50001`，只放 3 个 `ench`：`[5, 754, 90091]`**，其中 `5/754` 是 454 池里最稳的 2 条白字耐力系（已验证存在），`90091` 是你要的**全新附魔**（新 SIE，绿字 `type=3 EQUIP_SPELL`）。客户端看到的就是“2 白 + 1 绿，三选一”—— 词缀位够用，不用扩槽。

> 提问：为什么不直接改 454 池？—— 因为 454 是基线共享池，改它会污染全服其他用 454 的装备。新建 `50001` 最干净，回滚只要 `DELETE WHERE entry=50001`。

## 1. 4 步闭环（对应你说的 4 步，一步一校验）

### Step 1 — 造 SIE（1 条新附魔）

**文件：`outputs/p1_gen_sie_90091.json`**

```json
[
  {"0": 90091, "1": 3, "4": 0, "10": 21563, "13": "P1 New Enchant", "17": "P1全新附魔", "21": 4128894}
]
```

- `0=90091` 新 SIE ID（接在你 90001 段后，未占用）
- `1=3` → `EQUIP_SPELL`，才会显示**绿色**（你现在白色是 `type=1` 的 STAT）
- `10=21563` → **占位法术 ID，必须替换为你 `spell_template` 里真实存在的被动法术**（如你 Orange 池里已验证的战斗法术）。执行前务必 `SELECT entry FROM spell_template WHERE entry=21563;` 确认存在，否则 SIE 虽能进 DBC 但不生效
- `21=4128894` 固定
- `13/17` 英/中描述，绿字就靠它

> 最容易实现怎么来？—— 直接复用你 `trial_orange_enchants.csv` 里任意一个已验证的 `spell_id`（如 `2313`/`2351` 等），把 `10` 改成它即可，零新增法术。

**追加到服务端（dry-run 先过）：**

```bash
python _archive/tools_dbc/dbc_append.py /opt/soulcore-pb/server/data/dbc/SpellItemEnchantment.dbc outputs/p1_gen_sie_90091.json --string-fields 13 14 15 16 17 18 19 20 --dry-run
# 无 Error 后再去掉 --dry-run 真写
```

### Step 2 — 改 IRP（新建池 50001，扣 1 换 1）

**文件：`outputs/p1_gen_irp_50001.json`**

```json
[
  {"0": 50001, "1": "P0_IRP_50001", "2": 5, "3": 754, "4": 90091, "7": " of P1", "11": "之P1"}
]
```

- `0=50001` 新 IRP ID（与 `item_template.random_property` 对应）
- `1=P0_IRP_50001` internalName，随意，不影响玩家
- `2,3,4 = [5, 754, 90091]` → 2 条白字 + 1 条新绿字，三选一
- `7=enUS 后缀, 11=zhCN 后缀`（“之P1”），其他语言留空；想换名只改这俩 string

**追加：**

```bash
python _archive/tools_dbc/dbc_append.py /opt/soulcore-pb/server/data/dbc/ItemRandomProperties.dbc outputs/p1_gen_irp_50001.json --string-fields 1 7 8 9 10 11 12 13 14 --dry-run
```

> 校验：`7..14` 是 8 语言后缀，`1` 是 internalName；`dbc_append.py` 会自动把 string 追加到 string block 末尾并回写 `recCount/stringSize`。

### Step 3 — 建权重（DB 池）

**文件：`outputs/p1_weight_50001.sql`**

```sql
-- 库：tw_pb_world
DELETE FROM item_enchantment_template WHERE entry=50001;
INSERT INTO item_enchantment_template (entry, ench, chance) VALUES
(50001, 5,    33.33),
(50001, 754,  33.33),
(50001, 90091,33.34);
-- 校验：SUM 必须 100 ±0.1
SELECT entry, COUNT(*) c, SUM(chance) s FROM item_enchantment_template WHERE entry=50001 GROUP BY entry;
SELECT entry, ench, chance FROM item_enchantment_template WHERE entry=50001 ORDER BY ench;
```

赋给哪几件装备（复用 P0 的 3 白装做验证，验证通过再扩量）：

```sql
UPDATE tw_pb_world.item_template SET random_property=50001 WHERE entry IN (25,35,85) AND random_property IN (0);
-- 扩量示例（后续）：按等级段批量赋池，避开已赋池的
-- UPDATE item_template SET random_property=50001 WHERE quality IN (1,2) AND class IN (2,4) AND required_level BETWEEN 10 AND 60 AND random_property=0 LIMIT 100;
```

### Step 4 — 双重启（服务端 + 客户端）

**服务端（必须）：**

```bash
echo '<口令>' | sudo -S systemctl restart pbmangosd
journalctl -u pbmangosd -n 50 --no-pager | grep -iE "ItemRandomProperties|SpellItemEnchantment|Error"
```

**客户端（必须，缺一不可）：**
- 用 `build_client_patch.py` 的双文件版同时压 `DBFilesClient\SpellItemEnchantment.dbc` + `DBFilesClient\ItemRandomProperties.dbc` 进 `Data/patch-A.mpq`（复用你现有 `stormlibpy` 流程，`a.add_file(..., 'DBFilesClient\\...')` 两次）
- 玩家覆盖 `patch-A.mpq` 后重开客户端（或 `/reload` 不够，需重开）

> 为什么双 DBC 都要压？—— 服务端 90091 不进客户端，绿字不显示；IRP 50001 不进客户端，后缀名不拼。
