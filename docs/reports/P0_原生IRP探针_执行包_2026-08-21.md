### 1.2 为什么选 IRP 池 454

- `item_enchantment_template` 基线中 `entry=454` 拥有 16 条权重记录（`ench` 指向的 SIE 如 5/15/16/19… 均在基线 `SpellItemEnchantment.dbc` 存在），`SUM(chance)≈100`

- 客户端 `dbc.MPQ` 中同样存在该 IRP，**服务端与客户端同源，无需 patch-A**

### 1.3 链路图（A 探针，零新增 DBC）

## 2. 可执行 SQL（A 探针）

> ⚠️ **硬隔离红线**：本探针对 **tw_pb_world** 操作，严禁触碰生产 `tw_world`。执行前请确认连接的是 `tw_pb_world`。

```sql
-- P0-A 探针：零 DBC，复用 IRP 454，赋给 3 个白装
-- 适用库：tw_pb_world
-- 执行前备份（可选但推荐）：
--   CREATE TABLE tw_pb_world.item_template_p0bak_20260821 AS SELECT entry, name, quality, random_property FROM tw_pb_world.item_template WHERE entry IN (25,35,85);

-- 0) 自检：确认 3 个 entry 当前为 0，且 IRP 454 存在
SELECT entry, name, quality, class, subclass, random_property
FROM item_template WHERE entry IN (25,35,85);

SELECT COUNT(*) AS cnt_454, SUM(chance) AS sum_chance
FROM item_enchantment_template WHERE entry=454;
-- 预期：cnt_454 = 16，sum_chance ≈ 100（±0.2）

-- 1) 赋池（幂等：仅对 random_property=0 的赋，避免覆盖已有）
UPDATE item_template SET random_property = 454
WHERE entry IN (25,35,85) AND random_property = 0;

-- 2) 校验
SELECT entry, name, random_property FROM item_template WHERE entry IN (25,35,85);
SELECT entry, ench, chance FROM item_enchantment_template WHERE entry=454 ORDER BY chance DESC LIMIT 5;

-- 3) 回滚（探针结束后执行，二选一）
-- 方式一：精确回滚本次
-- UPDATE item_template SET random_property = 0 WHERE entry IN (25,35,85) AND random_property = 454;
-- 方式二：从备份表恢复
-- UPDATE item_template t JOIN item_template_p0bak_20260821 b ON t.entry=b.entry SET t.random_property=b.random_property;
```

**是否需要重启？**  
`item_template` 在 `ObjectMgr::LoadItemPrototypes` 时一次性加载进内存，**改 `random_property` 后必须 `systemctl restart pbmangosd`** 才能让新掉落/新创建的物品 roll 到新池。存量 `item_instance` 不追溯（见 §4）。

### 5.2 IRP 追加（1 条新池，enchant_id 指向 90091..90093）

IRP 的 WDBC 结构（见 `DBCStructure.h:405` / `DBCfmt.h: ItemRandomPropertiesfmt = nsiiixxssssssssx`）：

```
field 0: ID
field 1: internalName (string)
field 2..4: enchant_id[3] (uint32)
field 7..14: nameSuffix[8] (string, 0=enUS, 4=zhCN 等)
```

```python
# tools_dbc/gen_p0_irp.json  （IRP ID 50001，复用 SIE 90091..90093）
[
  {"0": 50001, "1": "P0_IRP_50001", "2": 90091, "3": 90092, "4": 90093, "7": " of P0", "11": " P0之"}
]
# python tools_dbc/dbc_append.py /opt/soulcore-pb/server/data/dbc/ItemRandomProperties.dbc tools_dbc/gen_p0_irp.json --string-fields 1 7 8 9 10 11 12 13 14 --dry-run
# （注意：IRP 的 string 字段含 internalName + 8 语言后缀，共 9 个 string 字段，具体下标以 DBCfmt 对齐为准，dry-run 会校验 fieldCount）
```

> 思考：为什么 IRP 的 `internalName` 与 `nameSuffix` 要分开？（一个给 DB/日志看，一个给玩家看；多语言后缀走 `nameSuffix[locale]`）
