## 2. 为什么“之熊”白板、“充实”白色、还出现无附魔？

**核心原因：SIE 754 在服务端根本不存在。**

```
服务端 SIE 存在性抽样（rc=21182）：
  5 ✅, 15 ✅, 16 ✅, 19 ✅, 25 ✅, 27 ✅, 754 ❌, 839 ❌, 1009 ❌, 1951 ✅, 115000 ✅(2313)
```

**推导：**

- IRP 51002 = `ench 754` → 指向不存在的 SIE → 客户端无绿字、服务端 `GetItemEnchantMod` 返回 0 → 物品 `randomPropertyId=0`（白板）
- IRP 51003 = `ench 115000(type3/2313)` → SIE 存在，但 2313 本身是“充实”类被动（全抗 50 点，effect 6），在 SIE 里 `type=3 EQUIP_SPELL` 会显示为白色（因为法术本身无颜色，颜色由 SIE type 决定，但你看到的“白色”其实是 SIE 描述文本颜色，非数值颜色；数值本身是 50 全抗，符合预期）
- 之耐力（5）有火舌 1 特效 → 说明 `type=1,3` 混合的 SIE 会同时给白字数值 + 绿字触发，这是 Turtle 基线 SIE 的特点

**权重层面的无附魔：** `50001 → 51001/51002/51003` 中 51002 因 SIE 缺失被内核判为无效 → 实际权重退化为 51001 vs 51003 二选一，51002 抽中即白板。

> 思考：如果你是内核，看到 `item_enchantment_template.ench` 指向的 SIE 不存在，你会怎么处理？（提示：`ItemEnchantmentMgr::GetItemEnchantMod` 打 Error 日志并返回 0，`SetItemRandomProperties` 不写入 PROP 槽）

## 4. 旧 Lua 是否干扰？

**结论：对 P1 白装（quality=1）无干扰，但对后续绿装扩量有干扰，建议隔离。**

- `random_enchant.lua` 核心过滤：`CFG.MIN_QUALITY=2` + `ALLOW_CLASS={[2]=true,[4]=true}` + 写 `PERM_SLOT=0`
- 原生 IRP 写 `PROP 3/4/5`，Lua 写 `PERM 0`，**槽位正交**，不会覆盖
- 但 Lua 会对 `quality≥2` 的绿装额外写 PERM，造成“原生白字 + Lua 绿字”叠加，若你要的是“原生三选一纯净验证”，Lua 的 PERM 会成为变量

**最干净的做法（待你确认）：**

```bash
# 备份并禁用（非删除），消除变量
sudo cp /opt/soulcore-pb/server/bin/lua_scripts/random_enchant.lua \
        /opt/soulcore-pb/server/bin/lua_scripts/random_enchant.lua.bak.$(date +%Y%m%d_%H%M%S)
sudo mv /opt/soulcore-pb/server/bin/lua_scripts/random_enchant.lua \
        /opt/soulcore-pb/server/bin/lua_scripts/random_enchant.lua.disabled
# 游戏内 .reload eluna 即可，无需重启
```

回滚：`mv *.disabled → random_enchant.lua && .reload eluna`

> 你希望现在就禁用以做“纯原生”对照，还是保留以观察“原生+Lua 叠加”？（P1 验证阶段我推荐前者，变量最少）
